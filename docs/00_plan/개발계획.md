## 3. 결정 사항 (OEM 확인 필요 가정)

OEM-SWR-001에 정의되지 않은 부분은 아래 공급자 가정으로 진행한다. 사용자가 2026-11-26에 권장안대로 진행하도록 승인했다. 각 가정은 SWE.1 산출물에 출처(D-xx)와 함께 기록하고, OEM 확인 질의 목록으로 유지한다.

| ID | 미정의 사항 | 결정 (공급자 가정) | 근거 |
|---|---|---|---|
| D-01 | 규칙 충돌 시 우선순위 | 높은 순서: ① 충돌 CONFIRMED → 좌·우 RELEASE (SR-001) ② sensor_fault 또는 DEGRADED → 직전 확정 출력 유지 (SR-004, SR-003) ③ 접근위험 TRUE → 해당 도어 LOCK (SR-002) ④ ignition_on=FALSE → 좌·우 RELEASE, OFF (FR-007) ⑤ 화재·과온·성인 탑승 → 좌·우 RELEASE (FR-005) ⑥ ISOFIX → 해당 도어 LOCK (FR-006) ⑦ 차속 ≥ 3.0 km/h → 좌·우 LOCK (FR-002) ⑧ 운전자 명령 (FR-001) | SR-001의 "다른 명령보다 우선" 문구. ASIL B 요구(②③)가 QM 요구(④~⑧)보다 먼저 적용되도록 해 QM 기능이 안전 기능을 무력화하지 못하게 함. 강제해제(⑤)는 탈출 목적이므로 강제잠금(⑥⑦)보다 우선 |
| D-02 | FR-003 override의 결과 | override는 상태(`OVERRIDE`)와 이유코드만 생성하고, 접근위험이 TRUE인 동안 출력은 LOCK을 유지한다 | FR-003 수용기준은 "override 상태와 이유코드 생성"만 요구. QM 요구가 ASIL B 억제(SR-002)를 해제하지 않도록 해 간섭을 배제 |
| D-03 | 평가 주기 | 50 ms 고정 주기 (100 ms = 2주기, 300 ms = 6주기) | SR-003(100 ms), SR-001(300 ms)을 주기 단위로 판정 가능 |
| D-04 | DEGRADED 상태의 출력, 필수 입력 | DEGRADED 진입 시 직전 확정 출력을 유지하고 새 운전자 명령을 적용하지 않는다(충돌 CONFIRMED는 예외, D-01 ①). 필수 입력은 VehicleSnapshot 전체이며 freshness는 `source_timestamp_s` 기준 | SR-004의 고장 반응(출력 유지)과 일관 |
| D-05 | 충돌 PENDING 처리 | PENDING은 CONFIRMED가 아니므로 해제하지 않고, 이유코드 `crash_pending`을 기록한다 | SR-001은 CONFIRMED만 해제 조건으로 정의 |
| D-06 | NFR-002 허용 필드 | `event_id`, `timestamp_s`, `state`, `lock_left`, `lock_right`, `priority_reason`, `reason_code`, `input_validity` | IF-006 표시 데이터와 결정 결과로 한정. 영상·음성·개인 식별자 없음 |
| D-07 | 차속 분해능 | 0.1 km/h | 경계값 시험(3.0 / 2.9 km/h)에 필요 |
| D-08 | 추적표의 SWR-019 결번 | 의도된 결번으로 보고 SWR-019는 사용하지 않는다. OEM 확인 질의로 유지 | OEM-SWR-001 9장에 SWR-019가 없음 |
| D-09 | Web 시뮬레이터 기술 | FastAPI(HTTP API) + 정적 HTML/JS | IF-006의 HTTP 500 요구를 충족하는 가벼운 구성 |
| D-10 | OEM 원본 문서 저장 | `OEM/` 폴더는 저장소에 커밋하지 않는다(`.gitignore`) | 원본에 "교육 과정 밖 배포 금지" 조건이 있음 |

아래 D-11~D-15는 1단계(SWE.1) 분석 중 새로 발견해 같은 원칙(안전 쪽, OEM 문구에 가장 가까운 해석)으로 정한 가정이다. 1단계 보고에서 사용자 확인을 받는다.

| ID | 미정의 사항 | 결정 (공급자 가정) | 근거 |
|---|---|---|---|
| D-11 | 시각 필드 이름 불일치 (IF-001 `source_timestamp_s`, IF-004 `VehicleSnapshot.timestamp_s`) | 같은 필드로 보고 `source_timestamp_s`로 통일 | 두 IF 모두 VehicleSnapshot의 시각을 가리킴 |
| D-12 | 충돌 해제 유지 기간 (SR-001 "이후 입력 주기에도 유지") | `ignition_on=false`가 될 때까지 RELEASE 유지 | 충돌 후 탈출 경로 확보. 시동 꺼짐은 FR-007로 어차피 해제 |
| D-13 | 무효 입력 처리 (SR-003 "정의된 방식") | 무효 VehicleSnapshot은 판정에 쓰지 않고 출력 유지, `INVALID` 표시. 유효 입력이 200 ms 넘게 없으면 DEGRADED | 무효 값으로 판정하지 않음. freshness 규칙과 일관 |
| D-14 | 기동 시 초기 상태 | 두 출력 RELEASE, `OFF`, `NO_DATA`. 첫 유효 입력 전 운전자 명령 미적용 | FR-007 "초기 해제 상태" |
| D-15 | 강제 해제 입력 동시 발생 시 이유 코드 | `fire` > `overtemperature` > `adult_present` 순서로 하나 기록 | 위험도가 큰 원인을 먼저 표시 |

## 4. 추적성과 검증

- OEM-SR/FR/NFR → SWR → 아키텍처·상세 설계 요소 → 소스·단위 테스트 → 통합 테스트 → 시스템 테스트 케이스를 ID로 양방향 추적한다.
- 테스트 이름과 docstring에 SWR ID를 적어 추적표를 자동으로 만들 수 있게 한다.
- OEM 수용기준은 각 SWR의 검증 기준으로 옮겨 G4 증거와 바로 연결한다.
