## 3. 유스케이스 상세

### UC-01 수동 잠금·해제
- **사전 조건**: 시동 ON, 정지(차속 3.0 km/h 미만), 유효 입력, 강제 규칙 없음
- **기본 흐름**: 1) 운전자가 `side`와 `action`을 선택해 명령한다. 2) SW가 명령을 검증한다. 3) 다음 평가주기에 지정 출력만 바꾼다. 4) 이유 코드 `driver_lock`/`driver_unlock`을 기록한다.
- **대안 흐름**: A1) 명령이 유효하지 않음 → 적용 안 함, `command_invalid`. A2) 상위 규칙이 적용 중(주행, ISOFIX, 시동 꺼짐, 강제 해제, 고장) → 해당 출력에 적용 안 함, `driver_rejected`. A3) 접근위험 도어 해제 요청 → UC-03.
- **사후 조건**: 지정 출력만 바뀌고 이벤트가 기록된다.

### UC-02 주행 시작 자동 잠금
- **사전 조건**: 시동 ON, 출력 RELEASE
- **기본 흐름**: 1) 차속이 3.0 km/h 이상이 된다. 2) 첫 평가주기에 두 출력을 LOCK으로 한다. 3) `auto_lock_speed`를 기록한다.
- **대안 흐름**: A1) 성인 탑승 등 강제 해제 입력이 있음 → RELEASE 유지(UC-05). A2) 차속이 다시 3.0 미만 → 잠금 유지.

### UC-03 하차 시 접근위험 억제와 override
- **사전 조건**: 정지, 후측방 접근위험 입력이 해당 도어에 true
- **기본 흐름**: 1) SW가 해당 도어를 LOCK으로 한다. 2) 운전자가 그 도어 해제를 요청한다. 3) SW가 해제를 억제하고 `approach_risk_<side>`를 기록한다. 4) 운전자가 10.0 s 이하에 같은 도어 해제를 다시 요청한다. 5) SW가 OVERRIDE 상태와 `approach_override_<side>`를 만들고, 접근위험이 true인 동안 LOCK을 유지한다.
- **대안 흐름**: A1) 10.0 s 초과 후 재요청 → 새 첫 억제. A2) 접근위험이 false가 됨 → OVERRIDE 종료, 이후 해제 요청은 UC-01.

### UC-04 충돌 긴급 해제
- **사전 조건**: 임의 상태
- **기본 흐름**: 1) `crash_status=CONFIRMED`가 들어온다. 2) 300 ms 이내에 두 출력을 RELEASE로 한다. 3) CRASH_RELEASE 상태를 시동 꺼짐까지 유지한다.
- **대안 흐름**: A1) `crash_status=PENDING` → 해제하지 않고 `crash_pending` 기록.

### UC-05 화재·과온·성인 탑승 강제 해제
- **기본 흐름**: 1) 화재, 과온, 성인 존재 중 하나가 true가 된다. 2) 다음 평가주기에 두 출력을 RELEASE로 한다. 3) 입력별 이유 코드를 기록한다.
- **대안 흐름**: A1) 해당 도어에 접근위험 true → 그 도어는 LOCK 유지(SWR-022 3순위).

### UC-06 ISOFIX 강제 잠금
- **기본 흐름**: 1) 한쪽 ISOFIX가 true가 된다. 2) 다음 평가주기에 그 도어만 LOCK으로 한다. 3) 반대쪽은 유지한다.

### UC-07 시동 꺼짐과 기동
- **기본 흐름**: 1) SW가 기동하면 두 출력 RELEASE, OFF, NO_DATA로 시작한다. 2) 첫 유효 입력에서 정상 판정을 시작한다. 3) `ignition_on=false`가 되면 첫 평가주기에 두 출력을 RELEASE, OFF로 한다.
- **대안 흐름**: A1) 시동 꺼짐 중 접근위험 도어 → LOCK 유지.

### UC-08 입력 이상 처리
- **기본 흐름(유효성)**: 1) 형식·범위 오류 입력을 받는다. 2) 판정에 쓰지 않고 출력을 유지한다. 3) INVALID, `input_invalid`를 제공한다.
- **기본 흐름(freshness)**: 1) 200 ms를 초과해 유효 입력이 없다. 2) 100 ms 이내에 DEGRADED, STALE이 되고 출력을 유지한다. 3) 유효 입력이 다시 오면 정상 판정으로 돌아간다.
- **기본 흐름(센서 고장)**: 1) `sensor_fault=true`. 2) 첫 평가주기부터 출력을 유지하고 FAULT, `W_SENSOR_FAULT`를 제공한다.

### UC-09 상태 조회·표시
- **기본 흐름**: 1) 표시 장치가 상태를 조회한다. 2) SW가 좌·우 출력, state, 입력 유효성, 판정 근거, 이유 코드, 경고 코드를 응답한다. 3) 화면에 표시한다.
- **대안 흐름**: A1) 직렬화 실패 → HTTP 500.

### UC-10 결정 이력 조회와 재생 검증
- **기본 흐름**: 1) 시험자가 고정 시계로 입력 벡터를 재생한다. 2) 결정 이력(최신 100건)을 조회한다. 3) 같은 벡터를 반복 재생해 결과 해시를 비교한다.
