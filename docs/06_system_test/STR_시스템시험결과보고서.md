## 4. 시험 과정의 독립성과 수정 이력

- 시험 케이스와 기대값은 `system-test-case` 서브 에이전트가 SWR 명세만을 베이시스로 설계했다(구현 코드를 기대값 근거로 쓰지 않음).
- 설계자가 초안 실행 중 기대값 오류 2건을 발견해 SWR 기준으로 고쳤다. 둘 다 구현 결함이 아니다.
  - TC-F-020: side=all 재입력이 override여야 하는데 억제로 적음 (SWR-006)
  - TC-F-024: 좌·우 동순위일 때 이유 코드는 좌측(SWR-022)인데 우측으로 적음
- 이후 별도 실행기(`tests/system/`)로 110건을 다시 실행해 위 결과를 얻었다.

## 6. 시험 설계자 질의(Q-01~09)와 처리

설계(SWD)와 구현이 이미 정한 동작을 답으로 적는다. SWR 문구로 명확히 하는 것이 좋은 항목은 "SWR 명확화"로 표시했다.

| ID | 질의 | 현재 동작 (근거) | 처리 |
|---|---|---|---|
| Q-01 | SWR-023 ① 주기 관측 방법 | Web 실제 시계 루프만 자율 주기. PC/SIL은 시험자가 구동 | 5장 미검증 범위 |
| Q-02 | 직렬화 실패 주입 | 시험 하네스에서 직렬화 함수 대체 (TC-F-096 구현과 같음) | 종결 |
| Q-03 | NaN/inf, 정수 속도, 2.95 km/h, 미래 시각 | NaN/inf 무효, 정수 유효, 2.95 유효(반올림 없음, DD-C03), 미래 시각 유효(검사 없음) (SWD 3.1) | SWR 명확화 후보 |
| Q-04 | 접근위험 false 후 재발생 시 override 창 | 초기화 (SWD 6장) | SWR 명확화 후보 |
| Q-05 | 무효 입력 + freshness 상실 동시 | `input_validity=INVALID`, state는 이전 값 유지 (SWD 9장 표) | 종결 |
| Q-06 | 충돌 확정 + 센서 고장/시동 꺼짐 시 state·경고 | state `CRASH_RELEASE`, 센서 고장이면 `W_SENSOR_FAULT` 유지 (SWD 5.5) | 종결 |
| Q-07 | 4~7순위가 명령을 막을 때 이유, PENDING 중 같은 상황 | 4~7순위는 `driver_rejected`(SWR-004 v1.1). PENDING이고 1~3순위가 없으면 `crash_pending`(SWR-008) | **SWR 명확화 필요**: SWR-004와 SWR-008이 같은 상황에 서로 다른 코드를 요구할 수 있음. 구현은 SWR-008 우선 |
| Q-08 | SWIF에 없는 추가 필드 | 무시하고 유효 처리 (SWD 3.1) | 종결 |
| Q-09 | DEGRADED 중·첫 입력 전 명령 | 폐기(매 주기 소비, SWD 9장) | 종결 |

SWR 명확화 후보(Q-03, Q-04, Q-07)는 다음 베이스라인 변경 요청(CR) 대상으로 남긴다. 현재 동작은 시험으로 고정되어 있어 변경 시 영향 범위를 바로 확인할 수 있다.
